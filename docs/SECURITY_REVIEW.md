# 보안 검토 — 2026-11-03

대상: v0.4.0 이후 `main`의 앱, 스크립트, 설치 프로그램, Windows CI.
방식: 수동 소스 검토, 공식 API 문서 확인, 회귀 검사. 침투 테스트나 보안 인증을 대체하지 않습니다.
수정은 `Unreleased`에 포함하며 기존 v0.4.0 릴리스 파일에는 소급 적용하지 않습니다.

## 신뢰 경계

- 앱과 설치 프로그램은 현재 사용자 권한을 사용합니다. 관리자 권한 실행을 전제로 하지 않습니다.
- 런타임에 네트워크 수신·원격 통신·업데이트 다운로드 기능이 없습니다.
- 프로세스 규칙은 전원 선택 기능이며 프로그램의 신뢰성이나 사용 권한을 판정하는 인증 수단이 아닙니다.
- 설정과 로그는 현재 사용자 AppData의 로컬 파일입니다. 동일 사용자 권한의 악성 프로세스를 격리하는 샌드박스는 아닙니다.
- 빌드는 신뢰하는 저장소 소스를 실행하는 개발 작업입니다. 배포 산출물의 코드 서명은 현재 구성되어 있지 않습니다.

검토 범위에서 원격 입력을 통한 코드 실행 또는 권한 상승 경로를 확인하지 못했습니다. 아래 항목은 주로 로컬 파일 무결성, 가용성, 실행 경로와 CI의 방어 강화입니다.

## 확인한 항목과 개선

| ID | 분류 | 기존 동작과 영향 | 조치 |
| --- | --- | --- | --- |
| SR-01 | 낮음 · 실행 경로 | `control.exe`를 이름으로 호출해 실행 파일 검색 경로에 의존. 작업 폴더 등에 파일을 둘 수 있는 행위자가 같은 사용자 권한의 실행을 유도할 여지가 있음 | 시스템 폴더의 절대 경로, 시스템 작업 폴더, 셸을 거치지 않는 실행으로 변경. 앱의 P/Invoke DLL 검색도 System32로 제한 |
| SR-02 | 보통 · 가용성 | 설정 파일 크기 확인 없이 전체 읽기, 로그 한 줄 무제한 읽기, 보관 처리 중 전체 생존 행 메모리 보관 | 설정 1MiB·JSON 깊이 16 제한. 로그 한 줄 128Ki 문자 제한. 보기 읽기는 최신 파일 끝부분부터 총 4MiB 이내. 보관 처리는 임시 파일에 순차 기록 |
| SR-03 | 보통 · 데이터 무결성 | 로그 폴더가 다른 폴더를 가리키는 junction이면 자동 보관 처리가 그 대상의 일치 파일을 변경·삭제할 수 있음. 해당 사용자 데이터 영역의 링크를 변경할 권한이 필요 | 데이터 폴더·로그 폴더의 재분석 지점 거부. 연결된 개별 로그 파일은 목록에서 제외하고, 쓰기 대상과 교체 전 경로를 재확인. 임시 파일은 `CreateNew`로 생성 |
| SR-04 | 낮음 · 규칙 정확성 | 이름과 경로를 서로 독립된 집합에서 확인하여 불일치하는 프로세스 스냅샷을 잘못 조합할 수 있음 | 같은 프로세스 레코드의 이름·전체 경로 쌍으로 매칭 |
| SR-05 | 낮음 · CI 방어 | checkout의 기본 자격 증명 보존 동작이 빌드 이후에도 필요 이상으로 유지될 수 있음. 현재 토큰은 이미 읽기 전용 | `persist-credentials: false` 설정. 기존 최소 권한·Actions SHA 고정·컴파일러 해시/서명 검증 유지 |

SR-01과 SR-03은 기존 사용자 권한 이상의 접근을 허용하는 것으로 입증된 항목이 아닙니다.
재분석 지점 확인은 경로 리디렉션 사고를 줄이는 사전 검사입니다. 같은 사용자에 의한 동시 파일 교체, 모든 상위 디렉터리 리디렉션, 하드 링크 공격을 원자적으로 차단하지는 않습니다.
데이터 폴더를 의도적으로 junction/symlink로 옮긴 환경은 해당 연결을 해제하거나 일반 폴더로 이전해야 합니다.

## 파일 및 JSON 처리

- `JavaScriptSerializer`는 타입 해석기를 지정하지 않은 생성자를 유지합니다. 임의의 .NET 타입을 해석하는 `SimpleTypeResolver`를 도입하지 않습니다.
- 파일 크기는 열린 읽기 핸들에서 확인하며, 읽는 동안 일반적인 동시 쓰기를 허용하지 않습니다.
- 크기 제한 또는 잘못된 로그 한 줄로 보관 처리에 실패하면 원본 파일을 교체하지 않고 임시 출력만 정리합니다.
- UI가 큰 로그의 마지막 일부만 읽더라도 저장된 이력을 잘라내지 않습니다. 화면에 일부 표시임을 알립니다.
- 0일 보관 설정은 그대로 자동 삭제를 중지합니다. 사용자가 선택한 이 경우 디스크 사용량에는 별도 상한이 없습니다.
- 보관 처리는 메모리 사용을 줄였지만 전체 파일을 검사하는 디스크 작업은 남아 있습니다. 매우 큰 로컬 이력은 처리 시간을 늘릴 수 있습니다.

## 검증

로컬에서 규칙·설정·로그 검사 52개와 junction 회귀 검사 6개, 총 **58개**를 통과했습니다.

- 과도하게 큰 설정을 역직렬화 전에 거부하고 원본 유지
- 4MiB를 넘는 로그에서도 최신 항목 표시 및 저장 이력 유지
- 대용량 로그의 순차 보관 처리
- 과도하게 큰 로그 한 줄 거부, 실패 시 원본 유지 및 임시 파일 정리
- 이름과 경로가 다른 프로세스에서 조합되는 잘못된 매칭 방지
- 로그 루트 junction을 통한 외부 파일 조회·추가·삭제 차단
- 설정 루트 junction을 통한 외부 설정 읽기·덮어쓰기 차단
- 데이터 폴더의 junction을 통한 로그 쓰기 차단

Windows CI는 같은 검사와 설치·업데이트·제거 검사 20개를 실행합니다. 결과는 [워크플로 기록](https://github.com/ParkDyel/PowerShift/actions/workflows/build.yml)에서 확인합니다.
검사에 쓰는 연결은 임시 폴더 안에서 생성하고, 대상을 재귀 삭제하지 않고 연결 자체를 제거합니다.
현재 실행 중인 사용자 앱과 설정은 이번 검토에서 교체하거나 변경하지 않았습니다.

## 남은 배포 과제

미서명 앱·설치·제거 파일의 Smart App Control 차단 문제는 이번 코드 개선으로 해결되지 않습니다.
신뢰된 코드 서명 인증서/서명 서비스를 준비해 전체 배포 산출물을 서명하고 검증해야 합니다.
같은 사용자 권한의 코드 실행, 설정·로그 변조나 이름만 지정한 프로세스 규칙의 이름 모방도 별도의 보안 경계로 보장하지 않습니다.
