# 변경 이력과 배포 절차

## 기록의 역할

| 위치 | 기록할 내용 |
| --- | --- |
| Git 커밋 | 구현 단위의 변경과 이유 |
| `CHANGELOG.md` | 사용자가 알아야 할 버전별 기능·수정·호환성·제약 |
| `docs/DESIGN.md` | 현재 구조, 동작 규칙, 데이터 형식, 주요 설계 판단 |
| GitHub Releases | 해당 버전 변경 요약, 다운로드 파일, 검증 결과와 필요한 안내 |

변경 이력의 기준은 저장소의 `CHANGELOG.md`입니다. Releases만 작성하면 소스 체크아웃이나 복제본에 설명이 함께 남지 않습니다.
기능 변경과 같은 커밋 또는 PR에서 `Unreleased`를 갱신하고, 구조나 동작 규칙이 달라지면 설계 문서도 갱신합니다.
문서만 보완한 경우에는 `Unreleased`에 기록하고 커밋·푸시합니다. 기존 릴리스 자산을 다시 만들거나 새 릴리스를 반드시 발행할 필요는 없습니다.

## 버전과 빌드

현재 배포 패키지는 0.4.1이며 앱 실행 파일의 내부 버전은 0.4.1.0입니다. 0.3.2와 0.4.0은 앱 기능을 바꾸지 않은 설치·배포 변경으로 당시 내부 버전 0.3.1을 유지했습니다.
설정 파일의 `Version = 1`은 별도의 데이터 스키마 버전입니다.

| 위치 | 버전 변경 시 확인 |
| --- | --- |
| `src/AssemblyInfo.cs` | 앱 구현을 변경한 경우 실행 파일 버전 |
| `installer/PowerShift.iss` | 기본 배포 버전 |
| `Build-Installer.ps1` | 기본 배포 버전과 출력 파일명 |
| `.github/workflows/build.yml` | 설치 검사 입력과 업로드 아티팩트 이름·경로 |
| `tests/InstallerTest.ps1` | 기대하는 설치된 앱 표시 버전 |
| `README.md` | 설치 파일 이름과 사용 예제 |

일반 빌드는 `Build.ps1`, 설치 빌드는 `Build-Installer.ps1`을 사용합니다. 설치 빌드는 기본적으로 앱도 다시 빌드합니다.
`-UseExistingBinary`는 앱 소스가 기존 바이너리와 일치함을 확인한 경우에만 사용합니다. 앱 변경이 있는데 오래된 EXE를 패키징하지 않도록 주의합니다.
개인 설정, 실제 사용 로그, 컴파일러 패키지, 작업 폴더와 로컬 바로가기는 배포에 포함하지 않습니다.

## 릴리스 순서

1. `Unreleased` 내용을 검토해 새 버전과 출시일 아래로 옮기고 새 `Unreleased` 영역을 만듭니다. 날짜는 Asia/Seoul 기준입니다.
2. 위 버전 참조를 함께 갱신하고 앱·설치 파일을 빌드합니다.
3. 변경에 맞는 검증을 수행합니다. 일반 규칙·저장은 `Test.ps1`, 실제 전환은 `-Integration`, 트레이는 `SmokeTest.ps1`, 설치는 `InstallerTest.ps1`을 사용합니다.
4. Windows CI 통과와 테스트한 산출물의 커밋을 확인합니다. OS 정책으로 로컬 실행이 차단됐으면 검증 환경과 한계를 릴리스에 명시합니다.
5. 신뢰된 코드 서명을 사용할 수 있는 배포에서는 앱, 제거 프로그램, 설치 컨테이너의 서명·타임스탬프를 검증합니다. 현재 배포 파이프라인에는 코드 서명이 구성되어 있지 않습니다.
6. 검증한 커밋에 `vX.Y.Z` 태그를 만들고 설치 EXE와 선택적인 ZIP을 GitHub Releases에 첨부합니다.
7. 릴리스 본문은 `CHANGELOG.md`의 해당 버전에서 발췌하고 설치 방법·호환성·서명 상태·검증 링크를 덧붙입니다.
8. 업로드 파일의 SHA-256이 검증한 산출물과 일치하는지 확인합니다. 출시 후 수정은 새 패치 버전으로 배포합니다.

GitHub CLI로 여러 줄의 릴리스 본문을 게시할 때는 UTF-8 파일과 `--notes-file`을 사용합니다.
GitHub의 커밋 기반 자동 릴리스 노트를 사용하더라도 프로젝트 `CHANGELOG.md`의 사용자 관점 설명을 검토해 반영합니다.

## 검증 증거

v0.4.0은 [Windows 빌드·설치 검증](https://github.com/ParkDyel/PowerShift/actions/runs/41603226113)을 통과한 설치 파일을 배포했습니다.
앱 검사 43개와 설치·업데이트·제거·데이터 보존 검사 20개가 포함됩니다.
미서명 산출물은 Smart App Control 등의 정책에 의해 실행이 제한될 수 있으므로 CI 성공을 모든 PC의 실행 허용으로 해석하지 않습니다.
